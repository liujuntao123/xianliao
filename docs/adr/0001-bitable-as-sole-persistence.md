# 飞书多维表格作为唯一持久化存储

本应用不使用任何传统数据库（连 SQLite 也不用），清单/任务/子任务/笔记全部持久化在用户飞书账号下的一个多维表格（Base）中，应用自身零本地持久化、重启即忘，唯一状态是环境变量。代价：所有读写经飞书 OpenAPI（读 20 QPS / 写 50 QPS、单表串行写），可用性依赖飞书。收益：数据主权在用户手里（随时在飞书里查看/导出/自动化）、self-hosted 零数据目录、天然多端。这个取舍是产品的立意本身，不是性能优化。

## Consequences

- 飞书 API 不可达时应用只读降级（缓存最近一次数据），不提供本地写队列。
- 记录结构受限于 Bitable 字段类型；复杂查询在应用侧内存完成（单用户数据量小）。
